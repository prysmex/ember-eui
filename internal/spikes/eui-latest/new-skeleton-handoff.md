# New components: EuiSkeleton* and EuiIllustration

Branch `eui-wave/new-skeleton`. Target EUI 123.1.0 / Borealis 8.1.0. Status: **Migrated** (full core suite passes in this worktree). These components did not exist in Ember EUI before.

## Components

All are Glimmer classes with `@cached` style getters, factories through `useEuiBorealisStyles`, and `@css` composed last.

| Component | Element (`...attributes`) | Args (defaults) | Blocks |
| --- | --- | --- | --- |
| `EuiSkeletonText` | loading `<span class="euiSkeletonText">` | `@lines` (3), `@size` `m`/`s`/`xs`/`relative` (`m`) + shared args | default = loaded content |
| `EuiSkeletonTitle` | loading `<span class="euiSkeletonTitle">` | `@size` `xxxs`…`l` (`m`) + shared | default |
| `EuiSkeletonCircle` | loading `<div class="euiSkeletonCircle">` | `@size` `s`/`m`/`l`/`xl` (`m`) + shared | default |
| `EuiSkeletonRectangle` | loading `<div class="euiSkeletonRectangle">` | `@width`/`@height` (`'24px'`, numbers → px), `@borderRadius` `s`/`m`/`none` (`s`) + shared | default |
| `EuiSkeletonLoading` | the `aria-busy` wrapper `<div>` | `@isLoading` (true), `@contentAriaLabel`, `@announceLoadingStatus` (false), `@announceLoadedStatus` (true), `@ariaLiveProps`, `@css` (wrapper) | `<:loadingContent as \|loading\|>` (yields `{ role: 'progressbar', ariaLabel }`), `<:loadedContent>` |
| `EuiIllustration` | `<span class="euiIllustration">` | `@type` `{ id, title, light, dark }` (required), `@alt` (asset title; `''` = decorative), `@fullWidth` (true), `@css` | none |

Shared skeleton args: `@isLoading`, `@contentAriaLabel`, `@announceLoadingStatus`, `@announceLoadedStatus`, `@ariaLiveProps` (`{ isActive, role, 'aria-live', focusRegionOnTextChange }`), `@ariaWrapperProps` (attributes for the wrapper; `className`/`class` add classes), `@css`.

## Behavior parity notes / Ember API differences

- As upstream, `...attributes` (upstream `rest`) go on the skeleton element, and the loading `role="progressbar"`/`aria-label="Loading {contentAriaLabel}"` override a caller `aria-label` (upstream `cloneElement` order). Without `@contentAriaLabel` the labels are `"Loading "` / `"Loaded "`, exactly like upstream's i18n interpolation of `undefined`. i18n tokens `euiSkeletonLoading.loadingAriaText` / `loadedAriaText`.
- `loadingContent`/`loadedContent` props are named blocks. Ember cannot clone a block's root, so `EuiSkeletonLoading` yields `{ role, ariaLabel }` for the caller to put on the loading root (the family components do this themselves).
- `ariaWrapperProps` is applied by the exported `applyAttributes` modifier (Glimmer cannot spread an object as attributes); previous values are restored when the props change.
- `EuiScreenReaderLive` did not exist in Ember EUI; ported privately as `eui-skeleton-loading/screen-reader-live.gts` (two alternating SR-only live regions, upstream toggle semantics; the swap after insertion/text change runs in a microtask tracked by `waitForPromise`). It could be promoted to a public `EuiScreenReaderLive` later.
- Live regions remount when `@isLoading` flips (two template branches), like upstream's two fragments.
- `EuiSkeletonRectangle` sets `inline-size`/`block-size` as inline style properties through a modifier, so they beat a caller's `style` width/height (upstream spreads `style` first) and other caller inline styles are kept. Caveat: if a caller's `style` attribute changes later, Glimmer rewrites the whole attribute and the sizes are only restored when `@width`/`@height` change.
- `@lines` is not clamped (upstream types it 1–10 but renders any count). `EuiLoadingContent` keeps its clamp.
- `EuiIllustration` inlines `@type.light`/`.dark` with `htmlSafe` (upstream `dangerouslySetInnerHTML`): trusted markup only, documented. Mode comes from the nearest provider (`context.colorMode`). `@elastic/eui-illustrations` is not a dependency; the docs demo defines a sample asset.

## EuiLoadingContent

Not delegated to `EuiSkeletonText`: behavior would change (adds the `aria-busy` wrapper div and "Loaded" live announcement, default 1 line vs 3, the 1–10 clamp, `euiLoadingContent`/`euiLoadingContent__singleLine` classes and `@singleLineClasses`). Both already use the same upstream `euiSkeletonTextStyles`, so visuals match. Deprecating it in favor of `EuiSkeletonText` is a possible follow-up decision.
